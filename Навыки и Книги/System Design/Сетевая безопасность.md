# Сетевая безопасность

## Короткая формула для запоминания

**Канал - Доступ - Периметр - Сеть - Мониторинг - Данные**

## Вопросы при разборе безопасности

- как защищаем передачу?
- кто имеет доступ?
- чем защищаем вход в систему?
- как разделена сеть?
- как узнаем об атаке?
- как защищаем данные и секреты?

## Проблемы, решения и инструменты

| Проблема | Решение | Инструменты / технологии |
| --- | --- | --- |
| Данные могут перехватить при передаче | Шифровать канал передачи | HTTPS, TLS |
| Нужно подтвердить, что сервер настоящий | Проверять сертификат сервера | TLS-сертификат, CA |
| Нужно, чтобы и клиент, и сервер подтверждали друг друга | Двусторонняя проверка сертификатов | mTLS |
| Сервис доступен из интернета напрямую | Закрыть прямой доступ, оставить только нужные входные точки | Firewall, Security Groups, Network ACL |
| Нужно безопасно подключаться к внутренней сети | Создать защищенный туннель | VPN, Site-to-Site VPN |
| Нужно защитить web/API от типовых атак | Фильтровать опасные запросы | WAF |
| Много подозрительных запросов или попыток подбора | Ограничить частоту запросов | Rate limiting, API Gateway, Redis |
| API перегружают большим количеством запросов | Ограничить и фильтровать трафик | DDoS protection, CDN, WAF, Rate limiting |
| Нужно скрыть внутреннюю структуру сервисов | Сделать единую контролируемую точку входа | API Gateway |
| Нельзя давать всем сервисам доступ ко всему | Разделить сеть на зоны | Network segmentation, VLAN, subnet, DMZ |
| Внутренней сети нельзя доверять по умолчанию | Проверять каждый запрос и каждый сервис | Zero Trust, mTLS, IAM, Service Mesh |
| Нужно понять, кто имеет доступ к функции | Описать роли и права | IAM, RBAC, ABAC |
| Пользователь может получить доступ к чужим данным | Проверять права на уровне объекта | Object-level authorization, ACL, ABAC |
| Нужно защитить админские функции | Ограничить доступ и усилить проверку | VPN, MFA, IP whitelist, RBAC |
| Нужно обнаруживать подозрительную активность | Собирать и анализировать события | IDS, SIEM, Security monitoring |
| Нужно автоматически блокировать атаки | Обнаруживать и блокировать подозрительный трафик | IPS, WAF, Firewall |
| Нужно расследовать инциденты | Хранить события и действия пользователей | Audit log, SIEM, Elasticsearch / OpenSearch |
| В логах могут утечь токены или персональные данные | Маскировать и ограничивать логирование | Log masking, data redaction |
| Данные могут украсть из БД или диска | Шифровать данные при хранении | Encryption at rest, TDE, KMS |
| Секреты могут попасть в код или конфиги | Хранить секреты отдельно | Vault, Secret Manager, KMS |
| Старый токен может быть использован повторно | Ограничить срок жизни и проверять актуальность | Short-lived tokens, refresh tokens, token revocation |
| Запрос может быть повторен злоумышленником | Защититься от replay attack | Timestamp, nonce, request signature, WS-Security |
| Нужно доказать, что сообщение не изменили | Подписывать сообщение | Digital signature, XML Signature, WS-Security |
| Нужно защитить SOAP-сообщение, а не только канал | Добавить безопасность на уровне сообщения | WS-Security |
| Внешняя интеграция должна быть доступна только партнеру | Ограничить доступ по сертификату или IP | mTLS, IP whitelist, VPN |
| Один сервис скомпрометирован - нельзя дать доступ ко всему | Минимизировать права и сегментировать доступ | Least privilege, Network segmentation, IAM |
| Нужно защитить от SQL injection / XSS | Фильтровать опасные payload и валидировать ввод | WAF, input validation, secure coding |
| Нужно контролировать доступ сотрудников | Централизованное управление учетками и правами | IAM, SSO, MFA |
| Нужно безопасно передавать файлы | Защищенный файловый обмен | SFTP, FTPS, VPN |
| Нужно контролировать действия администраторов | Логировать и ограничивать привилегированные действия | PAM, audit log, MFA |
