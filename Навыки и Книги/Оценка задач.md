# 1. Общий принцип оценки

Оценка = сумма работ по этапам + надбавки за сложность + неопределённость

---

# 2. Таблица этапов аналитики

| Этап                 | Что входит                                                   | Типовая оценка |
| -------------------- | ------------------------------------------------------------ | -------------- |
| Инициация            | Понять запрос, зафиксировать scope, определить стейкхолдеров | 1-3 ч          |
| Исследование (as is) | Разбор текущего процесса, систем, данных                     | 2-6 ч          |
| Проработка (to be)   | Бизнес-логика, сценарии, исключения                          | 4-12 ч         |
| Спецификация         | BPMN, user flow, API, ТЗ, mapping                            | 4-16 ч         |
| Согласование         | Встречи, правки, синхронизация                               | 2-8 ч          |
| Сопровождение        | Ответы dev/test, уточнения, дефекты                          | 2-10 ч         |

Итого базовая оценка: сумма всех этапов

---

# 3. Чеклист факторов сложности

Каждый фактор оценивается:

- 0 - нет
- 1 - низко
- 2 - средне
- 3 - высоко

| **Фактор**            | 0   | 1         | 2           | 3                        |
| --------------------- | --- | --------- | ----------- | ------------------------ |
| Количество систем     | 1   | 2         | 3           | 4+                       |
| Интеграции            | нет | простые   | средние     | сложные                  |
| Бизнес-роли           | 1   | 2         | 3           | 4+                       |
| Изменения UI\Frontend | нет | Изменения | Новый экран | Новый флоу\много экранов |
| Новые бизнес-правила  | нет | мало      | средне      | много                    |
| Исключения/edge cases | нет | мало      | средне      | много                    |
| Изменения данных      | нет | локальные | заметные    | сложные                  |
| Legacy/неизвестность  | нет | немного   | средне      | критично                 |
| Внешние команды       | нет | 1         | 2           | 3+                       |
| Регуляторика/риски    | нет | низкие    | средние     | высокие                  |

---

# 4. Надбавки к оценке

### 4.1. Интеграции

- +4-8 ч за каждую новую интеграцию
    

### 4.2. Коммуникации

| Участники | Надбавка |
| --------- | -------- |
| 1-2       | 0%       |
| 3-4       | +15-25%  |
| 5+        | +30-50%  |

### 4.3. Legacy / неизвестность

- лёгкая - +2-4 ч
    
- средняя - +4-8 ч
    
- высокая - +8-16 ч
    

---

# 5. Неопределённость (коэффициент)

| Уровень | Описание                 | Коэффициент |
| ------- | ------------------------ | ----------- |
| Низкий  | Всё понятно, есть аналог | x1.0        |
| Средний | Есть пробелы             | x1.2-1.4    |
| Высокий | Абстрактная идея         | x1.5-2.0    |

---

# 6. Разделение оценки (обязательно)

Всегда делить на 2 части:

| Блок      | Что включает                                       |
| --------- | -------------------------------------------------- |
| Discovery | Понять задачу, исследовать, снять неопределённость |
| Delivery  | Описать решение, согласовать, сопровождать         |

Пример:

- Discovery - 6 ч
    
- Delivery - 14 ч
    

---

# 7. Формула итоговой оценки

Итог = (Сумма этапов + надбавки) × коэффициент неопределённости

---

# 8. Пример использования

Допустим:

- базовые этапы = 20 ч
    
- интеграции = +8 ч
    
- коммуникации (4 человека) = +20%
    
- неопределённость = x1.3
    

Расчёт:

- 20 + 8 = 28 ч
    
- 28 × 1.2 = 33.6 ч
    
- 33.6 × 1.3 ≈ 44 ч
    

---

# 9. Допущения (обязательный блок)

Всегда фиксировать:

- без изменения системы X
    
- без новых ролей
    
- без изменений интеграции Y
    
- при наличии SME со стороны бизнеса
    

---
----
# 10. Быстрый чеклист перед оценкой

Перед тем как назвать часы, задать себе:

- Понятен ли scope?
- Сколько систем затронуто?
- Есть ли интеграции?
- Есть ли неизвестный as is?
- Сколько участников согласования?
- Есть ли исключения?
- Есть ли внешние команды?

Если ≥3 ответов "сложно" - оценка точно не должна быть "маленькой".
