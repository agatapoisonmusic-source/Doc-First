### Процесс проектирования системы

#### 1. **Понимание Проблемы**

**Действия аналитика:**

- Проводит встречи с заказчиком и стейкхолдерами, выявляет их потребности, ожидания и ограничения.
    
- Анализирует текущие бизнес-процессы, документы и регламенты.
    
- Формулирует проблему (Problem Statement) и ключевые цели проекта.
    
- Определяет основные термины и создает глоссарий для единого понимания.
    
- Составляет первоначальный список требований (User Stories, Use Cases, функциональные и нефункциональные требования).
    

**Артефакты:**

- Глоссарий терминов.
    
- Описание проблемы и целей проекта.
    
- Первичный список требований.
    
- Модель "как есть" (AS-IS) в виде BPMN-диаграмм (если требуется).
    

---

#### 2. **Концептуальное Проектирование**

**Действия аналитика:**

- Разрабатывает высокоуровневую концепцию решения, определяет основные компоненты системы.
    
- Создает сценарии использования (Use Cases) и user flow для ключевых процессов.
    
- Оценивает возможные архитектурные подходы и их соответствие бизнес-целям.
    
- Проводит workshops с командой и заказчиком для согласования концепции.
    

**Артефакты:**

- Концептуальная модель системы.
    
- Use Case-диаграммы и User Stories.
    
- BPMN-диаграммы "как будет" (TO-BE).
    
- Описание ключевых сценариев взаимодействия.
    

---

#### 3. **Функциональное Проектирование**

**Действия аналитика:**

- Детализирует функциональные требования, разбивает их на подзадачи.
    
- Проектирует логику работы системы: экраны, API, интеграции, бизнес-правила.
    
- Создает прототипы интерфейсов (wireframes, mockups) и согласует их с заказчиком.
    
- Уточняет требования к данным (сущности, атрибуты, связи).
    
- Проверяет, что все требования покрывают бизнес-потребности.
    

**Артефакты:**

- Детализированные функциональные спецификации.
    
- Прототипы интерфейсов (Figma, Balsamiq).
    
- Диаграммы последовательностей (UML Sequence).
    
- Уточненные User Stories с критериями приемки (Acceptance Criteria).
    

---

#### 4. **Техническое Проектирование**

**Действия аналитика:**

- Участвует в разработке технического задания (ТЗ), детализирует требования для разработчиков.
    
- Определяет форматы данных, API-контракты (Swagger/OpenAPI), интеграционные точки.
    
- Согласует выбор технологий с командой (например, СУБД, фреймворки).
    
- Формирует требования к тестированию (тест-кейсы, сценарии).
    
- Оценивает риски, сроки и ресурсы, помогает в планировании релизов.
    

**Артефакты:**

- Техническое задание (ТЗ) или Software Requirements Specification (SRS).
    
- ER-диаграммы и описание структуры данных.
    
- API-документация (Swagger/Postman).
    
- План тестирования и критерии успешного внедрения.
