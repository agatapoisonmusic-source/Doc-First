[[Проектирование]][[Проект API]]

Описание API в Swagger (или OpenAPI Specification) на языке YAML представляет собой структурированный способ описания всех аспектов вашего API, включая ресурсы, методы, параметры, коды ответов, аутентификацию и многое другое. Вот основные моменты, которые вам нужно знать:

### Основные понятия в Swagger:

1. **Swagger (OpenAPI) файлы**: Это YAML-файлы (.yaml или .yml), которые описывают ваше API. Они содержат всю информацию, необходимую для понимания и использования вашего API.
    
2. **Swagger Editor**: Интерактивный инструмент, который позволяет визуально создавать и редактировать Swagger-спецификации. Он предоставляет автодополнение, валидацию и предварительный просмотр вашей спецификации.
    
3. **Основные разделы в Swagger файле**:
    
    - **openapi**: Версия OpenAPI Specification (например, "3.0.0").
    - **info**: Информация о вашем API, такая как название, описание, версия.
    - **servers**: URL-адреса серверов, на которых доступно API.
    - **paths**: Описание доступных путей (endpoints) API, их параметры, методы (GET, POST и т.д.) и коды ответов.
    - **components**: Повторно используемые компоненты, такие как схемы данных, параметры, аутентификация и др.

### Алгоритм создания Swagger файла:

1. **Определение информации о вашем API**:
    
    - Укажите название, версию, описание.
    - Задайте базовый URL для всех путей (например, [https://api.example.com](https://api.example.com/)).
2. **Описание путей (paths)**:
    
    - Для каждого ресурса вашего API определите соответствующий путь.
    - Для каждого пути укажите доступные методы (GET, POST и т.д.), параметры запроса, коды ответов.
3. **Описание параметров**:
    
    - Опишите параметры запроса (query parameters), параметры пути (path parameters) и заголовки запроса (header parameters), которые ваш API использует.
4. **Описание кодов ответов**:
    
    - Укажите все возможные коды ответов (200, 404, 500 и т.д.) и их описание.
    - Для каждого кода ответа укажите схему ответа (например, JSON объект).
5. **Описание схем данных (components)**:
    
    - Определите схемы данных (schemas), используемые в запросах и ответах.
    - Можно использовать референсы на схемы данных для повторного использования.
6. **Описание безопасности (security)**:
    
    - Укажите методы аутентификации и авторизации, используемые вашим API (например, OAuth 2.0).

### Важные аспекты при создании Swagger файла:

- **Согласованность**: Используйте единый стиль и структуру для описания всех путей и компонентов API.
- **Понятные названия**: Используйте четкие и лаконичные названия для путей, параметров и схем данных.
- **Документация**: Добавляйте описания и комментарии, чтобы облегчить понимание вашего API другим разработчикам.
- **Валидация**: Проверяйте ваш Swagger файл на соответствие спецификации с помощью инструментов вроде Swagger Editor или онлайн-валидаторов.

### Пример YAML файла Swagger:

```
openapi: 3.0.0
info:
  title: My API
  description: Description of my API
  version: 1.0.0
servers:
  - url: https://api.example.com
paths:
  /users/{id}:
    get:
      summary: Get user by ID
      parameters:
        - name: id
          in: path
          required: true
          schema:
            type: integer
            format: int64
      responses:
        '200':
          description: Successful response
          content:
            application/json:
              schema:
                type: object
                properties:
                  id:
                    type: integer
                    example: 1
                  name:
                    type: string
                    example: John Doe
components:
  schemas:
    User:
      type: object
      properties:
        id:
          type: integer
        name:
          type: string

```



Этот пример демонстрирует базовую структуру Swagger файла, описывающего путь `/users/{id}` для получения пользователя по его ID.

Следуя этим рекомендациям, вы сможете создать полноценное описание вашего API в Swagger, которое будет четким, понятным и легко поддерживаемым другими разработчиками.




### Примеры описания элементов:

#### 1. Описание обычного параметра:

```
parameters:
  - name: id
    in: query
    required: true
    schema:
      type: integer
      format: int64
    description: ID of the user

```

В данном примере:

- `name`: Название параметра (`id`).
- `in`: Где параметр передается (`query` означает в строке запроса).
- `required`: Обязательный ли параметр (`true`).
- `schema`: Схема параметра, включая тип данных (`integer`) и формат (`int64`).

#### 2. Описание объекта:

```
schemas:
  User:
    type: object
    properties:
      id:
        type: integer
        format: int64
      name:
        type: string

```

В данном примере:

- `User`: Имя схемы данных.
- `type`: Тип объекта (`object`).
- `properties`: Свойства объекта, включая `id` (целое число типа `int64`) и `name` (строка).

#### 3. Описание массива объектов:

```
schemas:
  UsersList:
    type: array
    items:
      $ref: '#/components/schemas/User'

```

В данном примере:

- `UsersList`: Имя схемы данных для списка пользователей.
- `type`: Тип данных (`array`).
- `items`: Описание элементов массива. В данном случае, элементы это объекты, описываемые с использованием ссылки на другую схему (`$ref`).

#### 4. Описание объекта с массивом:

```
schemas:
  UserWithOrders:
    type: object
    properties:
      id:
        type: integer
        format: int64
      name:
        type: string
      orders:
        type: array
        items:
          $ref: '#/components/schemas/Order'
  Order:
    type: object
    properties:
      orderId:
        type: integer
        format: int64
      orderDate:
        type: string
        format: date-time

```

В данном примере:

- `UserWithOrders`: Объект пользователя с массивом заказов.
- `orders`: Поле в объекте пользователя, содержащее массив заказов, каждый из которых описывается с использованием схемы `Order`.
- `Order`: Схема данных для объекта заказа, содержащая поля `orderId` (целое число типа `int64`) и `orderDate` (строка в формате даты и времени).

Эти примеры помогут вам начать работу с описанием вашего API в Swagger на YAML. Каждый из них демонстрирует основные концепции, такие как параметры запроса, объекты данных, массивы и использование ссылок для повторного использования схем данных.
