### 1. **User Story Mapping**

- **Как проводится:**
    - Выберите команду и соберите ее в одном месте (или используйте онлайн-инструмент).
    - Определите пользователя (персону), для которого создается карта.
    - Определите основные активности, которые пользователь выполняет.
    - Разделите каждую активность на подзадачи или пользовательские истории и расположите их на доске.
    - Обозначьте приоритеты и зависимости между историями.
- **Как используется:** Используется для визуализации функционала, упрощая понимание пользовательских потребностей и взаимодействий.
- **Преимущества:**
    - Помогает увидеть целостность пользовательского опыта.
    - Упрощает приоритизацию и планирование.
    - Стимулирует совместную работу команды.
- **Ограничения:**
    - Може быть сложным для масштабных проектов с большим количеством функций.
    - Требует времени для участия всей команды.

### 2. **Jobs To Be Done (JTBD)**

- **Как проводится:**
    - Определите целевую аудиторию и сессии с пользователями.
    - Проведите интервью, в которых выясните, какие задачи пытается решить пользователь с помощью вашего продукта или услуги.
    - Опишите задачи, выделяя основные «работы» и соответствующие контексты.
- **Как используется:** Используется для фокусировки разработки на удовлетворении реальных потребностей пользователей, а не на функции продукта.
- **Преимущества:**
    - Позволяет глубже понять потребности пользователей.
    - Повышает вероятность успеха, сосредоточив внимание на реальных нуждах.
- **Ограничения:**
    - Углубленные интервью могут занять много времени.
    - На решения могут влиять "Шум" вокруг предоставленных данных.

### 3. **Карта гипотез**

- **Как проводится:**
    - Соберите команду и выделите время для обсуждения идей.
    - Идентифицируйте гипотезы, относящиеся к продукту, функциям и пользователям.
    - Визуализируйте гипотезы, создавая карту с указанием ключевых направлений и их взаимосвязей.
- **Как используется:** Используется для структурирования идей и планирования тестирования гипотез.
- **Преимущества:**
    - Помогает определить приоритеты для дальнейших исследований.
    - Упрощает обсуждение и анализ для команды.
- **Ограничения:**
    - Гипотезы могут быть неточными или требовать уточнения.
    - Может привести к избытку идей, если не будет четкой структуры.

### 4. **Дерево метрик**

- **Как проводится:**
    - Определите ключевые бизнес-метрики вашего продукта.
    - Составьте иерархическую структуру метрик, включая показатели верхнего уровня и подкатегории.
    - Обсуждайте как каждая метрика связана с бизнес-целями и функциональностью.
- **Как используется:** Используется для оценки успеха продукта и взвешивания влияния изменений.
- **Преимущества:**
    - Помогает в визуализации целей и связанных показателей.
    - Способствует более обоснованным решениям на основе измеримых данных.
- **Ограничения:**
    - Может быть сложным в разработке для многофункциональных продуктов.
    - Требует доступа к данным и инструментам мониторинга.

### 5. **Пользовательские интервью и опросы**

- **Как проводится:**
    - Определите целевую аудиторию для интервью.
    - Создайте вопросы и проведите сессии, где пользователи делятся своекопами и опытом.
    - Анализируйте полученные данные на предмет выявления общих тем.
- **Как используется:** Используется для сбора обратной связи и понимания потребностей пользователей.
- **Преимущества:**
    - Предоставляет конкретную информацию из первых уст.
    - Позволяет выявить неожиданные потребности и проблемы пользователей.
- **Ограничения:**
    - Могут возникнуть предвзятости в ответах.
    - Требует времени и ресурсов для проведения и анализа.

### 6. **Диаграмма Исикавы (рыбья кость)**

- **Как проводится:**
    - Определите проблему, которую нужно решить.
    - Создайте «костяную» структуру, обозначив основные категории причин.
    - Обсудите подкатегории причин до тех пор, пока не будут выявлены основные коренные причины.
- **Как используется:** Используется для выявления проблем и причин их возникновения.
- **Преимущества:**
    - Помогает организовать мысли и выявить области, требующие внимания.
    - Фокусирует обсуждение на причино-следственных связях.
- **Ограничения:**
    - Результат может быть субъективным.
    - Может потребовать много времени для проведения обсуждений.

### 7. **Анализ конкурентов**

- **Как проводится:**
    - Сформируйте список основных конкурентов и их продуктов.
    - Проанализируйте функционал, ценные предложения, отзывы и маркетинговые стратегии.
    - Выделите сильные и слабые стороны конкурентов, а также возможные возможности для вашего продукта.
- **Как используется:** Используется для понимания конкурентного ландшафта и выявления уникальных предложений.
- **Преимущества:**
    - Помогает выявить недостатки текущего продукта.
    - Упрощает выявление уникальных возможностей и конкурентных преимуществ.
- **Ограничения:**
    - Может не учитывать изменения на рынке.
    - События вокруг конкурентной среды могут изменяться.

### 8. **Customer Journey Mapping**

- **Как проводится:**
    - Определите целевую аудиторию и ключевые этапы взаимодействия с продуктом.
    - Сформируйте визуализацию «пути пользователя», описывая взаимодействие на каждом этапе и возникающие эмоции.
    - Выявите точки боли и возможности для улучшения на каждом этапе.
- **Как используется:** Используется для понимания пользовательского опыта и возможности улучшения.
- **Преимущества:**
    - Помогает увидеть полное взаимодействие пользователя с продуктом.
    - Выявляет проблемные моменты и возможности для улучшений.
- **Ограничения:**
    - Може потребовать значительных усилий для построения.
    - Путь пользователя может изменяться со временем.

### 9. **Kano Model**

- **Как проводится:**
    - Определите функции и характеристики вашего продукта.
    - Проводите опросы, чтобы выяснить, как пользователи относятся к каждой функции (удовлетворенность, необходимость и т. д.).
    - Классифицируйте функции по категориям: базовые, производительные и привлекательные.
- **Как используется:** Используется для определения приоритетов функций на основе их влияния на удовлетворенность пользователей.
- **Преимущества:**
    - Позволяет эффективно приоритизировать функции на основе ожиданий пользователей.
    - Помогает избежать избыточных функций и сосредоточиться на реальных потребностях.
- **Ограничения:**
    - Может потребовать много времени для проведения и анализа опросов.
    - Не все функции легко поддаются классификации.

Эти техники служат мощными инструментами для генерации идей и создания бэклога, и их выбор должен основываться на специфике продукта, цели проекта и ресурсах команды.
