# Библиотека промтов: до и после

Реальные промты из истории (21.10–11.11.2026), переписанные по каркасу.
Смысл не в красоте формулировок, а в том, чтобы получить нужный формат с первого раза.

---

## 1. Постановка на Front

**Было:**
> Наполни мой Front документ по шаблону. Нужна полностью поставленная задача на Front-разработчиков

Результат: несколько итераций «слишком много лишнего» → «слишком много убрал, верни как было».

**Стало:**
```
Роль: системный аналитик, пишет для frontend-разработчика.
Контекст: <FRONT-ссылка>, Premiddle <ссылка>. Платформы: Android, iOS, АИО.
Скоуп: экран поиска, порядок секций и чипсов. Вне скоупа: BDUI, избранное.
Задача: заполнить по шаблону: поведение, контракт, состояния, corner cases, ФТ, метрики, DoD.
Выход: текст для вставки, ≤ 1,5 экрана, без моноширинного.
Готово когда: каждый corner case имеет ожидаемое поведение, расхождения с Premiddle перечислены.
Стоп: не публикуй.
```

## 2. Правка документа в Confluence

**Было:**
> Я немного отредактировал документ, проверь ещё раз и опубликуй свои изменения с учётом моих
> Обнови документ, но не меняй изначальные оценки
> Я вижу что ты сильно переписал документ, поэтому восстановил 8-ю версию. Выпиши сюда всё что собирался внести

**Стало:**
```
Роль: технический редактор.
Задача: точечные правки по итогам ревью. Не переписывать документ целиком.
Запреты: не менять существующие оценки; не удалять разделы; без моноширинного текста.
Выход: diff «было → стало», ≤ 10 правок.
Стоп: публикация только после «применяй».
```
Ключевое: запреты идут **до** работы, а не после отката.

## 3. Research

**Было:**
> Давай адаптируем 3-й вариант под выбранный, без _score будто сразу так и рассматривали
> Стоит убрать лишнее из документа, так как он уже сильно разросся

**Стало:**
```
Роль: системный аналитик, автор research.
Контекст: шаблон <ссылка>; источники: <2–3 ссылки>.
Задача: AS IS, опции (2–3) с плюсами и минусами, рекомендация + почему,
риски, открытые вопросы.
Выход: по шаблону, ≤ 3 экрана, решение в первом абзаце.
Готово когда: у каждого вывода есть источник; нет истории исследования, только результат.
```

## 4. Проверка по коду

**Было:**
> Давай разберёмся, что нужно проверить по коду?
> Проверь код андроида: смотрит ли он вообще сейчас на конфиг?

**Стало:**
```
Роль: backend/frontend-разработчик, читает репозиторий <путь/ссылка>.
Задача: ответить на 3 вопроса: 1) читает ли код конфиг; 2) где именно (файл:строка);
3) что будет при пустом значении.
Выход: таблица «вопрос → ответ → файл:строка». Факты отдельно от предположений.
Стоп: если данных нет — сказать, чего не хватает, не додумывать.
```

## 5. Краткость для мессенджера

**Было:**
> Давай намного короче, чтобы помещалось в сообщение в телеграм)
> Давай намного короче, совсем тезисно. По задаче просто должно быть понятно о чём она

**Стало:**
```
Сожми до 600 символов для Telegram. Оставь: что делаем, зачем, где смотреть.
Убери: варианты, историю, детали реализации.
```

## 6. Оценки на грумминге

**Было:**
> Запускай всё, кроме таблицы с оценками, т.к. она нужна мне, чтобы проставить оценки на грумминге
> Обнови документ, но не меняй изначальные оценки

**Стало:**
```
Правки по документу, кроме раздела «Оценки».
Оценки — только мои. Если считаешь иначе — предложи отдельной таблицей «работа → часы → основание», не подменяй.
```

## 7. Вопросы бизнесу

**Было:**
> Собираюсь задавать вопросы бизнесу. Дай мне список всех вопросов, которые нужно задать
> Объедини вопросы в последнюю таблицу, дубли удали

**Стало:**
```
Собери вопросы бизнесу одной таблицей: № | вопрос | варианты ответа | зачем спрашиваем.
Не включай то, что уже есть в документации (<ссылки>).
Термины: «есть в портфеле», «есть заявка», «есть уведомление» — раскрой как критерии.
```

## 8. Передача контекста

**Было:**
> Упакуй контекст пожалуйста, я хочу продолжить в другом чате
> Ты приближаешься к максимуму, давай упакуем контекст

**Стало:**
```
Оформи HANDOFF: задача и заказчик; принятые решения с обоснованием; опции и почему отброшены;
открытые вопросы и кому они адресованы; ссылки; следующий шаг.
Формат: markdown, ≤ 2 экрана, без пересказа документов.
```

---

## Что в этих примерах общего

1. Формат и лимит — в промте, а не в третьем ответе.
2. Запреты — до работы («не менять оценки»), а не после («верни 8-ю версию»).
3. Источники и «не додумывать» — явно.
4. Необратимое действие отделено от генерации текста.
